
## Commercial Licensing & Capability-Driven Architecture

All code interacting with licensing, tier capabilities, quotas, feature gating, or Store products MUST strictly adhere to these standards:

### 1. 100% Capability-Driven Model (No Hardcoded Plan Names)
- **Never Hardcode Plan Names**: **Never** check or branch on literal plan names (e.g., `plan === "business"`, `plan === "enterprise"`, `plan === "single"`, `plan === "trial"`).
- **Stateless Capability Enforcement**: Licensing is governed strictly by the signed cryptographic token's capabilities (`limits`, `stages`, `entitlements`, `channel`).
- **All checks must use `@jchat/runtime-remix` (in Remix 3 apps) or `@jchat/runtime` helper functions**:
  ```ts
  import {
    canCreateMultiSite,
    getMaxSites,
    getReleaseChannel,
    hasCapability,
    hasStageAccess,
    isMultiSiteAllowed
  } from "@jchat/runtime-remix"
  ```

### 2. Runtime Capability Resolvers
Always query the dedicated helper from `@jchat/runtime-remix` (or `@jchat/runtime` in `apps/chat`) rather than manually decoding or parsing JWT claims:
- **Site Quotas**: Use `getMaxSites(token)` (returns a `number`). Guard site creation by comparing `currentCount >= getMaxSites(token)`.
- **Multi-Site Capability**: Use `canCreateMultiSite(token)` or `isMultiSiteAllowed(token, domain, installationId)`.
- **Feature Lifecycle Stages**: Use `hasStageAccess(token, stage)` where `stage` is `"stable" | "beta" | "experimental"`.
- **Specific Feature Entitlements**: Use `hasCapability(token, entitlement)` (e.g., `hasCapability(token, "branding.custom_themes")`).
- **Release Channel**: Use `getReleaseChannel(token)` (returns `"stable" | "lts"`).

### 3. Store Catalog & Immutable Order Snapshotting
- **Catalog Products (`store_products`)**:
  - Plans define their capabilities via the `capabilities` JSONB column (`StoreProductCapabilities`).
  - Capabilities structure:
    ```ts
    export interface StoreProductCapabilities {
      maxSites: number
      stages: ("stable" | "beta" | "experimental")[]
      entitlements: string[]
      channel?: "stable" | "lts"
      trialDays?: number
      maxRoomsPerSite?: number
      [key: string]: unknown
    }
    ```
- **Immutable Snapshot Guarantee**:
  - When an order is placed, `store_orders.snapshot_capabilities` permanently snapshots `product.capabilities`.
  - Future catalog price or capability adjustments **never** alter existing purchases. Existing customers retain their exact purchase terms forever.

### 4. 3-Tier Feature Flag Resolution
Every platform capability resolves dynamically across three decoupled layers:
$$\text{Effective State} = \text{Platform Gate} \land \mathbf{License\ Stage/Entitlement} \land \text{Site Admin Toggle}$$

1. **Platform Safety Gate**: Environment control (e.g. `ENABLE_EXPERIMENTAL_FEATURES`).
2. **License Gate**: Checked via `hasStageAccess(token, feature.stage)` and `hasCapability(token, capability)`. If locked, show upgrade lock badge in Admin Labs.
3. **Site Admin Toggle**: Stored in site settings; admin can toggle features enabled by their license.

### 5. Addon Licensing & Entitlements
- Commercial addons require an `entitlement.json` containing an HMAC-SHA256 signature generated by the Store.
- Addon entitlements are cryptographically bound to the host license ID via `@jchat/runtime`.
- Addons must never bypass or alter host license validation.
